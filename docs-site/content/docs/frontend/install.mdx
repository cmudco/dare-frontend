The DARE frontend is a static single-page application built with Vite. Two deployment paths:

1. **Docker path** — build once, serve via Nginx (recommended for production)
2. **Bare-metal path** — serve `dist/` directly from any static host or behind any reverse proxy

For environment variable reference, see [docs/configuration.md](/docs/frontend/configuration).

---

## Prerequisites

| Requirement                                | Version | Notes                                              |
| ------------------------------------------ | ------- | -------------------------------------------------- |
| Node.js                                    | 18+     | 20 LTS recommended                                 |
| npm                                        | 9+      | (or `pnpm` / `yarn` if you adapt scripts)          |
| A running `DARE backend` | —       | Reachable from the browser via the configured URLs |

## Path 1: Docker

A minimal multi-stage Dockerfile:

```dockerfile
# build stage
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
ARG VITE_DJANGO_BACKEND_URL
ARG VITE_WEBSOCKET_URL
ENV VITE_DJANGO_BACKEND_URL=$VITE_DJANGO_BACKEND_URL
ENV VITE_WEBSOCKET_URL=$VITE_WEBSOCKET_URL
RUN npm run build

# serve stage
FROM nginx:1.27-alpine
COPY --from=build /app/dist /usr/share/nginx/html
COPY devops/nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
```

A SPA-friendly Nginx config (`devops/nginx.conf`):

```nginx
server {
    listen 80;
    server_name _;
    root /usr/share/nginx/html;
    index index.html;

    # Cache static assets aggressively
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # SPA fallback — let React Router handle the path
    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

Build and run:

```bash
docker build \
    --build-arg VITE_DJANGO_BACKEND_URL=https://api.example.com \
    --build-arg VITE_WEBSOCKET_URL=wss://api.example.com \
    -t dare-frontend .

docker run -d -p 80:80 --name dare-frontend dare-frontend
```

> **Important:** Vite inlines `VITE_*` values at build time. Changing `VITE_DJANGO_BACKEND_URL` at runtime has no effect — you must rebuild the image. Pass the per-environment URLs as build args.

## Path 2: Bare Metal

### 1. Install Node and dependencies

```bash
# install Node 20 (Ubuntu example)
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo bash -
sudo apt install -y nodejs

# in the project directory
npm ci
```

### 2. Configure environment

```bash
cp .env.example .env
# edit .env — see docs/configuration.md
```

Minimum:

```
VITE_APP_ENVIRONMENT=production
VITE_DJANGO_BACKEND_URL=https://api.example.com
VITE_WEBSOCKET_URL=wss://api.example.com
```

### 3. Build

```bash
npm run build
```

Produces a static bundle in `dist/`.

### 4. Serve `dist/`

You have several options:

**Nginx (recommended)** — copy `dist/` to `/var/www/dare-frontend` and use the SPA fallback config above.

**Static hosting** — upload `dist/` to S3 / Cloud Storage / Cloudflare Pages / Netlify / Vercel. Configure SPA-style routing (rewrite all paths to `/index.html`).

**Node-based static server (for staging)**:

```bash
npx serve -s dist -l 5173
```

### 5. CORS and CSRF

The backend must include the frontend's origin in `CORS_ALLOWED_ORIGINS` and `CSRF_TRUSTED_ORIGINS`. See the [backend configuration reference](/docs/backend/configuration).

For Socket.IO connections to succeed, the WebSocket URL (`VITE_WEBSOCKET_URL`) must be reachable from the browser and must accept the same authentication token used for REST.

## Development workflow

```bash
npm install      # one-time
npm run dev      # http://localhost:5173 with HMR
npm run lint     # ESLint
npm run format   # Prettier
npm run build    # verify production build before merging
```

A pre-commit hook (Husky + lint-staged) runs ESLint and Prettier on staged files.

## Verifying the install

After deploying:

1. Visit the deployed URL — the login screen should load.
2. Open browser dev tools → Network. Sign in. Verify:
   - The REST request hits `VITE_DJANGO_BACKEND_URL`.
   - The Socket.IO upgrade succeeds (look for `wss://` 101 status).
3. Send a chat message. You should see streamed tokens arrive.
4. Upload a file. It should reach `processing` then `completed` status.

If any of those fail, check the browser console for CORS or auth errors and verify the backend's `CORS_ALLOWED_ORIGINS` includes your origin.

## Upgrading

```bash
git pull
npm ci         # respect lockfile
npm run build
# redeploy dist/ via your usual mechanism
```

For Docker-based deployments, rebuild the image with the appropriate build args and redeploy the container.

## Troubleshooting

| Symptom                                      | Likely cause                                                    | Fix                                                                                   |
| -------------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| White screen, console error about asset 404s | Server not serving SPA fallback (deep links 404)                | Configure `try_files $uri /index.html` or equivalent                                  |
| `Network Error` on every request             | Wrong `VITE_DJANGO_BACKEND_URL`, or CORS not allowed by backend | Verify URL; add origin to backend `CORS_ALLOWED_ORIGINS`                              |
| Chat connects but no streamed tokens         | Socket.IO URL or auth issue                                     | Check `VITE_WEBSOCKET_URL`; inspect WS frames in dev tools                            |
| Build fails with TS errors                   | Type drift after backend API changes                            | Update `redux/types/`; run `npx tsc --noEmit` for full report                         |
| Old code shipped after deploy                | CDN or browser cache                                            | Ensure `index.html` is `Cache-Control: no-cache`; assets fingerprinted (Vite default) |
| `VITE_*` env var ignored at runtime          | Vite inlines at build time                                      | Rebuild with the desired value                                                        |

For more, see [CONTRIBUTING.md](/docs/frontend/contributing).
